- Some notes:
* -- The Alt/F10 logic works like this:
      Alt or F10 — enters "menu mode", focusing the menu bar and highlighting the first item. The app is now in a keyboard navigation state.
      Arrow keys — left/right moves between top-level items, down opens the dropdown for the focused item.
      Enter — activates the focused item.
      Escape — steps back one level (closes dropdown → back to menu bar → exits menu mode).
      Alt+letter — jumps directly to a menu item by its underlined letter (called an accelerator or mnemonic), e.g. Alt+F opens "File". These underlines are hidden by default in modern Windows and only appear once you press Alt.
      The way Windows handles this under the hood is through a WM_SYSKEYDOWN message for Alt (rather than WM_KEYDOWN), and the default window procedure (DefWindowProc) implements all of this menu bar navigation logic for you automatically if you have a menu attached to the window. F10 specifically sends a WM_SYSKEYDOWN with VK_F10, which DefWindowProc also handles.
      --
      So in practice if you're building a standard Win32 window with a HMENU attached, you get all of this for free without writing any of the navigation logic yourself.
